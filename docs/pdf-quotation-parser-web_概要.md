# pdf-quotation-parser-web 概要

## 背景・課題

- **PDFデータの属人化・分散管理**: 取引先商社（岩瀬産業等）から受領する見積書PDFが個別に保管され、過去の単価推移や同等品の比較検索が困難。
- **手入力による転記コストと誤り**: 見積内容を手動でシステムや台帳に入力・集計することによる工数負担および入力ミスの発生。
- **後続プロセスの非効率**: 受領した見積明細をもとにした自社発行の見積依頼書・発注書の作成に再転記の手間が発生。
- **セキュリティ・アーキテクチャの刷新**: 元PDFを外部サーバーに送信せずブラウザ内で完結させるセキュアな構成、および過去のSQLite/Node.jsベースからモダンな完全BaaS（Supabase）基盤への移行による一元管理の実現。

## ターゲットユーザ

- **資材調達・購買担当者**: 商社からの見積書受領、過去単価の横断検索・比較、見積依頼書・発注書の作成業務を行う担当者。
- **業務管理者 / バックオフィス**: 取引先商社マスタや製品マスタの整備、調達履歴の監査ログ管理、複数テナント/ユーザー単位でのセキュアな情報管理を行う管理者。

## 主要機能一覧 (MUST/SHOULD)

### MUST

- **クライアントサイドPDF解析**:
  - ブラウザ内（`pdf.js`）でのテキスト抽出およびヘッダー・明細の正規化（元PDFをサーバーへ送信しないゼロサーバー構成）。
  - SHA-256ハッシュによる受領見積書の重複取り込み防止と監査ログ記録。
- **直感的なUI/UX・編集グリッド**:
  - ドラッグ＆ドロップ（D&D）による見積書アップロード。
  - 元PDFと抽出結果を突き合わせる2画面プレビュー。
  - インライン行編集および小計・合計の自動再計算グリッド。
- **検索・明細活用**:
  - カナ揺れ（全角・半角・濁点等）を吸収する柔軟な検索。
  - 複数キーワードAND検索。
  - 明細のお気に入り登録・管理。
  - 複数見積から明細をピックアップして合算できる「買い物かご」機能。
- **帳票・連携データ生成**:
  - 日本語フォント埋め込みによる自社見積依頼書・発注書のPDF自動生成（`pdf-lib`）。
  - 機密情報（価格・社名等）をマスキング可能なAI連携用Markdown出力。
- **マスタ管理・認証基盤**:
  - 自社情報設定（`user_settings`）、取引先商社マスタ（`suppliers`）、製品マスタ（`product_master`）。
  - Supabase AuthおよびRow Level Security (RLS) によるテナント・ユーザー間のセキュアなデータ分離。

### SHOULD

- **商社別パーサー分離アーキテクチャの拡充**:
  - 岩瀬産業以外の多様なフォーマット・商社向け解析ルールのプラグイン化・拡充。
- **外部サービス連携**:
  - Gmail API連携による見積依頼・発注メールの下書き自動作成機能。
