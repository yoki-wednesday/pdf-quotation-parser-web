### 【Background & Purpose】
- 岩瀬産業等の見積書PDFをブラウザ上で解析し、Supabaseへ一元管理するWebアプリケーション（React SPA）の構築。
- 過去の単価推移の横断検索、買い物かご機能による複数明細の合算、および自社発行の見積依頼書・発注書の自動生成（日本語PDF）を実現し、調達業務を効率化する。
- （注: 過去のSQLite/Node.jsベースのバックエンド構成や、config.json等のローカルファイル管理手法は破棄し、完全なBaaSベースのモダンSPAへ移行・統合済みである。）

### 【Decisions】
- **技術スタック**: React 19, TypeScript, Vite, Supabase, `pdfjs-dist`, `pdf-lib`, Vitest
- **要件定義 (MUST)**:
  - **PDF解析**: クライアントサイドでのテキスト抽出、ヘッダー/明細正規化、SHA-256ハッシュによる重複防止
  - **UI/UX**: 2画面プレビュー、行編集/再計算グリッド、D&Dアップロード
  - **検索/連携**: カナ揺れ吸収検索、複数キーワードAND検索、お気に入り管理、買い物かご機能
  - **帳票出力**: 日本語フォント埋め込みPDF生成（見積依頼書・発注書）、AI連携用Markdown出力（機密情報マスキング）
  - **マスタ管理**: 自社設定、取引先、未登録製品の管理、Auth/RLSによるテナント分離
- **アーキテクチャ・モデリング**:
  - **Serverless SPA**: 元PDFをサーバー・クラウドへ送信せず、ブラウザ内(`pdf.js`)で抽出完結させ、構造化データのみをSupabase(REST API)へ送信するゼロサーバー構成。
  - **ID・データ設計**: 全エンティティのPKに時系列ソート可能な`UUIDv7`を採用し、`auth.uid() = user_id` によるRow Level Security (RLS) を全テーブルに適用。
  - **UI要素識別子**: 全UI操作要素へテスト・自動化用のKebab-case識別子 (`data-ai-id`) を強制。
- **データスキーマ**:
  - `users`: プロファイル (auth.users連携)
  - `user_settings`: 自社設定 (1:1)
  - `suppliers`: 取引先商社マスタ
  - `estimates` / `estimate_items`: 受領見積および明細データ
  - `import_logs`: PDF取り込み監査ログ (ハッシュによる重複管理)
  - `product_master`: 製品マスタ
  - `procurement_projects`: 発注・見積依頼履歴
  - `favorite_items`: お気に入り明細
- **リリース・運用**:
  - 本番バンドルビルド (`npm run build`) 前にTypeScript型チェックとVitestによる自動テスト (カバレッジ80%超) をCI/CDで強制。
  - SLI/SLO: 静的ホスティング稼働率99.95%以上、PDF解析1.5秒以下等の定量的基準を定義。
  - 自動ロールバック: デプロイ直後スモークテストやクラッシュ急増時に即時切り戻しを実行。
- **実装状況 (Phase 6.10まで完了)**:
  - `tasks.md` に定義された全40タスク（Task-001〜040）の実装および単体・結合テストが完了（ALL PASS）。
  - 直近の実装として、AI向けMarkdownマスキング（Phase 6.9）、複数キーワードAND検索とお気に入り管理（Phase 6.10）が本番統合済み。
