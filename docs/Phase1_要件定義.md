# Phase 1 要件定義 (Requirement Definition)

## 1. 背景・課題

- **PDFデータの属人化・分散管理**: 取引先商社（岩瀬産業等）から受領する見積書PDFが個別に保管され、過去の単価推移や同等品の比較検索が困難。
- **手入力による転記コストと誤り**: 見積内容を手動でシステムや台帳に入力・集計することによる工数負担および入力ミスの発生。
- **後続プロセスの非効率**: 受領した見積明細をもとにした自社発行の見積依頼書・発注書の作成に再転記の手間が発生。
- **セキュリティ・アーキテクチャの刷新**: 元PDFを外部サーバーに送信せずブラウザ内で完結させるセキュアな構成、および過去のSQLite/Node.jsベースからモダンな完全BaaS（Supabase）基盤への移行による一元管理の実現。

## 2. 生データ分析・ニーズ構造化 (MUST/SHOULD/COULD)

### MUST (必須要件)
- **クライアントサイドPDF解析**: ブラウザ内（`pdf.js`）でのテキスト抽出およびヘッダー・明細の正規化。元PDFをサーバーへ送信しないゼロサーバー構成。
- **重複防止**: SHA-256ハッシュによる受領見積書の重複取り込み防止と監査ログ記録。
- **直感的なUI/UX・編集グリッド**: ドラッグ＆ドロップ（D&D）による見積書アップロード、元PDFと抽出結果を突き合わせる2画面プレビュー、インライン行編集および小計・合計の自動再計算グリッド。
- **検索・明細活用**: カナ揺れ（全角・半角・濁点等）を吸収する柔軟な検索、複数キーワードAND検索、明細のお気に入り登録・管理。
- **買い物かご機能**: 複数見積から明細をピックアップして合算できる機能。
- **帳票・連携データ生成**: 日本語フォント埋め込みによる自社見積依頼書・発注書のPDF自動生成（`pdf-lib`）、機密情報（価格・社名等）をマスキング可能なAI連携用Markdown出力。
- **マスタ管理・認証基盤**: 自社情報設定、取引先商社マスタ、製品マスタの管理。Supabase AuthおよびRow Level Security (RLS) によるテナント・ユーザー間のセキュアなデータ分離。

### SHOULD (推奨・望ましい要件)
- **商社別パーサー分離アーキテクチャの拡充**: 岩瀬産業以外の多様なフォーマット・商社向け解析ルールのプラグイン化・拡充。
- **外部サービス連携**: Gmail API連携による見積依頼・発注メールの下書き自動作成機能。

- [UNSPECIFIED]

## 3. ゴール(KPI)

- **システム完全移行**: 旧SQLite/Node.js構成から、BaaS(Supabase)・Serverless SPA構成への100%移行完了。
- **パフォーマンス**: クライアントサイドでのPDF解析処理を1.5秒以下で完了させる。
- **可用性・安定性**: 静的ホスティング稼働率99.95%以上。
- **品質保証**: CI/CDにおける自動テスト（Vitest）のカバレッジ80%超を維持。
- **業務効率化**: 見積明細の手入力・転記作業にかかる時間をゼロ化し、検索および帳票作成の工数を大幅削減する。

## 4. ユースケース

- **見積書の取り込み**: 担当者が受領した見積書PDFをブラウザにD&Dし、即座に内容が解析・一覧化される。
- **解析結果の確認・修正**: 解析された見積明細と元PDFを左右画面で比較し、必要に応じてブラウザ上で単価や数量を修正（自動再計算）して保存する。
- **過去単価の検索**: 新たな見積依頼を行う際、過去の同等品の単価をキーワード（カナ揺れ許容）で検索し、最安値や過去の取引履歴を確認する。
- **発注・見積依頼の作成**: 必要な明細を「買い物かご」に追加し、合算した上で自社フォーマットの「発注書」または「見積依頼書」PDFを自動生成、ダウンロードする。

## 5. 機能要件

- **認証・認可**: Supabase Authを用いたユーザーログイン。RLSによるデータアクセスコントロール（自社データのみアクセス可能）。
- **PDF解析機能**: `pdf.js`を利用したローカルでのテキスト・構造抽出処理。
- **データ登録・重複チェック**: ファイルのSHA-256ハッシュ計算によるインポート済ファイルブロック、および監査ログへの記録。
- **UIコンポーネント**: プレビューア、編集可能なデータグリッド（再計算ロジック内包）、買い物かごドロワー、設定モーダル。
- **検索機能**: Supabaseの全文検索またはRPCを活用したカナ揺れ吸収・複数キーワードAND検索インターフェース。
- **PDF出力・エクスポート機能**: `pdf-lib`を利用した日本語フォント埋め込みPDF出力、およびマスキング処理ロジックを含むMarkdownエクスポート。

## 6. 非機能要件

- **アーキテクチャ**: 完全なBaaSベースのServerless SPA（ブラウザ完結での重処理実行、データストアはSupabase REST API/PostgreSQL）。
- **技術スタック**: React 19, TypeScript, Vite, Supabase, `pdfjs-dist`, `pdf-lib`, Vitest。
- **セキュリティ**: 元ファイル（PDF）の外部送信禁止。すべてのデータベーステーブルにおける `auth.uid() = user_id` を用いたRLS適用。
- **データモデル・識別子**: 全エンティティの主キー（PK）に時系列ソート可能な `UUIDv7` を採用。
- **テスト・自動化容易性**: 全てのUI操作要素に対して、テスト・自動化用のKebab-case識別子（`data-ai-id`）を付与することを強制。
